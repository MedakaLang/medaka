`aacol` and `zzcol` each declare a type spelled `Col` with DIFFERENT constructor sets
(`{Red}` vs `{Red, Blue}`). The entry takes only the value `aval` from `aacol` and

constructors — and the entry's single-arm `match` is non-exhaustive. `W-NONEXHAUSTIVE`

runtime never reaches the missing arm: `run`/`build` are exit 0 printing `6` under both
orderings, and the DIAGNOSTIC is the whole observable (the `codes=` component of this
gate's signature is what grades it).

`UseGroup` alone; `UseWild` fell through the `_ _ _ = []` fallback, so a wildcard
import contributed NO import-scoped overlay and the constructor occurrence was decided
by bare-name first-match over the flat load-ordered universe. Measured on a binary
cold-built from sprint/ctor-identity @ c7c879b7, both orderings of exactly these two
clauses:

    `import aacol.{aval}` then `import zzcol.*`  -> codes={}                  (warning LOST)
    `import zzcol.*` then `import aacol.{aval}`  -> codes={W-NONEXHAUSTIVE}   (warning present)

i.e. the two orderings disagreed, and the first is the loud->silent direction AGENTS.md
grades as a severity increase. The sibling `over_ctors` shape (aacol having MORE ctors)
diverges the other way, emitting a spurious `W-NONEXHAUSTIVE` naming a constructor the
entry cannot name.
