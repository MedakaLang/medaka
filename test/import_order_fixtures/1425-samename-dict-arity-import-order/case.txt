## WHY THIS FIXTURE EXISTS WHERE IT DOES

The `dict_fixtures/` copy is graded by `test/diff_compiler_dict_semantics.sh`, whose two
structural rows for this shape (`^define i64 @mdk_lefty__widget\(i64 %arg0, i64 %arg1\)`
and `^define i64 @mdk_righty__widget\(i64 %arg0\)`) read the EMIT path. `runEmitWith` runs
`mangleUnits` BEFORE `elaborateModules`, which makes the emitter's bare keys accidentally
identity-bearing -- so those rows are STRUCTURALLY INCAPABLE of failing on this defect
class however broken the eval path is, and its value row could not see it either, because
the define and the call site agreed on the same phantom dict slot and the printed number
came out right by accident. This gate grades `check` + `run` + `build` + the EXECUTED
BINARY across EVERY ordering, which is what actually reaches the defect.

## HOW THE EXPECTED VALUES WERE ESTABLISHED

in DICT-SEMANTICS §8 I1, independently of any engine: dictionary arity is keyed by BINDING
IDENTITY, so `lefty.widget` abstracts one dict and `righty.widget` abstracts none;
`L.widget (1 : Int)` = `sz 1 + 100` = 101 and `R.widget 1` = 201. Both orderings must
print `101` then `201`.

it was built for is FIXED in the same PR that adds it -- it is the regression guard, which
is what the ledger header prescribes a drained case becomes.
