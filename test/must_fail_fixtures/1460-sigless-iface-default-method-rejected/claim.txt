issue: 1460
what: an interface method written with a BODY AND NO SIGNATURE (`helloI x = ...`
what: with no `helloI : ...` line) is UNCONDITIONALLY rejected on any interface
what: with at least one parameter -- there is no way to write one. The parser
what: (`ifaceMemberRest`, compiler/frontend/parser.mdk) stamps the member with a
what: placeholder type `IfaceMethod name (TyVar "_") ...`, and `phantomMethodMsg`
what: (compiler/types/typecheck.mdk) accepts only if `anyMember (tyVarNames mty)
what: typarams` holds -- `tyVarNames (TyVar "_")` is `["_"]`, which is never an
what: interface parameter name, so for non-empty `typarams` the reject branch can
what: never be avoided. The compiler's own placeholder leaks into the user's face:
what: three of the four diagnostics talk about a type variable `_` that the author
what: never wrote, and NONE of them says the signature is missing.
what: Measured first-hand on a cold-bootstrapped binary: `check main.mdk` -> exit 1
what: with the four diagnostics pinned below, and `run main.mdk` -> exit 1 with the
what: same four (so it is not a `check`-only quirk). Adding the one missing
what: signature line clears all four (control.mdk: check exit 0, run prints
what: "Hello World").
