what: At a MULTI-PARAMETER interface, a binding's inferred context is rendered over type
what: variables that the rendered TYPE never binds. `check --types` prints
what:     h : Conv c d => a -> b -> String
what: for `h x y = conv (Wrap x) (Wrap y)`. `c` and `d` appear nowhere in `a -> b ->
what: String`, so the signature reads as a constraint on escaped/ambiguous variables — i.e.
what: exactly like a dict-routing bug. It is not one: the scheme itself is right and only
what: its RENDERING is wrong (see why-cosmetic).
what: CORRECT rendering, derived by hand and NOT captured from any tool: the goal at h's
what: body is `Conv (Wrap a) (Wrap b)`, which discharges through
what: `impl Conv (Wrap a) (Wrap b) requires Conv a b`; the `requires` leaves the residual
what: `Conv a b` over h's OWN two argument types. Those are the same two variables the type
what: prints as `a` and `b`, so one letter allocation across the whole scheme must print
what:     h : Conv a b => a -> b -> String
what: A constraint variable that IS a type variable must print with the same letter, and a
what: constraint over a variable absent from the type should not be renderable at all.
