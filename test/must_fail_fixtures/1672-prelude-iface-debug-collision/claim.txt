what: A user interface method named `debug` (`dmod.mdk`: `interface D a where debug :
what: a -> String`, `impl D Int where debug x = "d"`) collides, by bare spelling, with
what: the implicit PRELUDE's OWN interface method `Debug.debug : a -> String`
what: (stdlib/core.mdk:335-339). `main.mdk` imports it SELECTIVELY
what: (`import dmod.{debug}`) and calls `debug 5 == "d"`. `check` and `check --json` are
what: BOTH clean (exit 0, zero diagnostics on every file). `medaka run` -- the
what: tree-walking interpreter -- prints `False` at exit 0. The BUILT native binary,
what: executed, ALSO prints `False` at exit 0. All three execution channels (run,
what: build, executed binary) silently agree on the SAME wrong value, with NO
what: diagnostic anywhere on any channel.
what: THE CORRECT ANSWER, HAND-DERIVED FROM THE DECLARATIONS ONLY (never from an
what: engine -- every engine here is wrong and agrees, so none of them is an oracle for
what: this claim): `import dmod.{debug}` is an ordinary selective import; its entire
what: documented purpose (AGENTS.md: "an import must say what it binds") is to bind the
what: bare name `debug`, in the importing module, to `dmod`'s `D.debug`. The only
what: `impl D Int` in scope returns the literal string "d" for any Int receiver, so
what: `debug 5` denotes "d" under that binding, and `debug 5 == "d"` denotes `True`.
what: `False` is therefore wrong under the declarations alone, independent of what any
what: engine computes.
what: WHAT THIS FIXTURE DOES NOT DECIDE: whether the CORRECT fix is "route the call to
what: the user's D.debug" (the reading above), "reject the program as an ambiguous /
what: colliding declaration", or some other resolution, is the SAME open class question
what: already sitting on #1182 (two interfaces sharing a bare method name; order-
what: dependent selection) -- here the implicit prelude occupies one side of the
what: collision instead of a second user module. That adjudication is explicitly NOT
what: made by this fixture; see the issue body's "Adjudication" section. This claim only
what: asserts the CURRENT observable (silent wrong value on every channel) still
what: reproduces.
what: GOVERNING TEXT: NOT SHADOW-SEMANTICS / S1-PRELUDE (docs/spec/SHADOW-SEMANTICS.md,
what: #1375/#1499) -- that ruling is scoped to a PRELUDE STANDALONE (a bare function,
what: no interface) colliding with a user interface method. Here BOTH sides are
what: interface methods (`D.debug` and the prelude's own `Debug.debug`), so S1's
what: shadow-hood conjunct (`funDef-names(...) ∩ ...`) has an EMPTY left operand and is
what: vacuously false; S2/S2-DECL never fire either. The governing text is instead
what: DICT-SEMANTICS §6 C1 + C4/I2 (docs/spec/DICT-SEMANTICS.md) -- the same governing
what: text as #1182's class question -- cited, not decided, here.
what: `compiler/DIAGNOSTIC-CODES-DESIGN.md`'s `R-DUPLICATE-IFACE-METHOD` row names this
what: exact axis ("a collision with a prelude interface method is left exactly as it
what: behaves today") and points at issue #1672 (this issue) as of this PR.
what: MECHANISM, read from the emitted LLVM IR (`medaka build --keep-ir` on this exact

what: a WRONG-IMPL-SELECTION defect at the call site: the import is silently ignored and
what: the collision resolves in favor of the prelude every time. UNESTABLISHED beyond
