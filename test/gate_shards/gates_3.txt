ROW IDENTITY, NOT PLACEMENT. Which gates run here is DERIVED
(`medaka gate balance`, #2178) from test/gate_cost_baseline.json and
regenerated into this matrix by `make gen-ci`; it changes whenever the
baseline does, so nothing below names a gate. What this row is:

wasm_arm = true  -> installs wasm-tools + Node and builds the Wasm
oracle. This is one of only two OPEN rows that carry it (the other is
`gates_8`), so it is one of only two rows a wasm-constrained gate can
legally land on — the balancer treats that as a hard constraint, never
as a cost, and refuses to pack rather than schedule such a gate where
its toolchain is absent.

full_cores = false, so the row shares a runner and the balancer may put
any number of gates here. In practice it often holds very few: the
single most expensive gate in the suite has to sit somewhere, and a row
already at the pole cannot take another gate without raising it.

The row NAME is a required status-check context (`gates_3`), so renaming it
is a ruleset change, not an edit here. It is a bare executor number by
construction (#2178): a name that cannot describe contents cannot lie
about them. What failed is reported by AREA, from the registry.
