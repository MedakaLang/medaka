ROW IDENTITY, NOT PLACEMENT. Which gates run here is DERIVED
(`medaka gate balance`, #2178) from test/gate_cost_baseline.json and
regenerated into this matrix by `make gen-ci`; it changes whenever the
baseline does, so nothing below names a gate. What this row is:

full_cores = true  -> the whole runner, and CLOSED TO THE PACKER. Gates
whose `shard` says `gates_1` stay here; the balancer never moves one in
or out. That is deliberate: `diff_compiler_engines` is irreducible (every
fixture pays a full `medaka build` + clang, on THREE engines) and wants
the box rather than its own ENGINE_JOBS=NCPU/2 hedge. The cost is that
this row runs below the median row load by construction — re-examine the
closure if that gap ever stops being worth it.

wasm_arm = true  -> installs wasm-tools + Node and builds the Wasm
oracle, so this row's T2/T3 tiers actually run; MEDAKA_REQUIRE_WASM=1
makes a degraded run a hard fail rather than a quiet skip.

The row NAME is a required status-check context (`gates_1`), so renaming it
is a ruleset change, not an edit here. It is a bare executor number by
construction (#2178): a name that cannot describe contents cannot lie
about them. What failed is reported by AREA, from the registry.
