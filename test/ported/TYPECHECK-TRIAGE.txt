test/ported/TYPECHECK-TRIAGE.txt — why each `medaka check` diagnostic in this corpus exists
============================================================================================

Issue #1445 decided: no silent typecheck skips in `medaka test`.  `test/ported/*.mdk` is the
reason a module-level exemption still exists, on the belief that the corpus is untypecheckable
by design.  This file records the FIRST measurement of that belief (2026-08-09, cold-built
binary at merge-base of the branch, human `medaka check`, exit code read without a pipe).

The belief is mostly WRONG.  Of 23 diagnostics across the three gate targets, 13 were
incidental, 4 were essential divergence, 6 were compiler bugs, and 0 were code defects.
⚠️ Don't trust that split — DERIVE it from the rows below, which are the actual record:
  grep -cE '\((A|B|C|D)\)$' test/ported/TYPECHECK-TRIAGE.txt   # 23
  grep -c '(A)$' …   # 13     grep -c '(B)$' …   # 4
  grep -c '(C)$' …   # 0      grep -c '(D)$' …   # 6
(An earlier revision of this line said 14/4/5, having counted submod.mdk's (D) outside
the (D) column.  The rows were right; the summary was not.)
The 6 internal-primitive POLICY rows at the end are not part of that 23 — they are a
flag question, not a triage bucket.

Buckets
-------
  (A) INCIDENTAL — the assertion does not need the rejected construct; a type annotation or a
      missing method signature makes it check clean without changing what it tests.  FIXED.
  (B) ESSENTIAL  — the rejected construct IS the test (an eval-vs-check divergence assertion).
      ISOLATED into a named file; never "fixed", because removing the construct deletes the
      coverage rather than passing it.
  (C) DEFECT     — the code is wrong and the checker is right.  (None found.)
  (D) COMPILER BUG — the checker is wrong to reject.  Reported, NOT worked around.

Reproduce
---------
  ./medaka check test/ported/test_run_ported.mdk
  ./medaka check test/ported/test_loader_ported.mdk
  ./medaka check --allow-internal test/ported/test_eval_ported.mdk
(Without `--allow-internal` the third reports only the 6 internal-primitive policy rows and
suppresses everything else — the resolve pass fails before typecheck runs.)

test_run_ported.mdk — 1 diagnostic
--------------------------------------------------------------------------------------------
501:53  Ambiguous instance for `Ord`  (`expectTrue (pingP 5 : Bool)`)                      (A)
        `pingP`/`pongP` are an unannotated mutually-recursive pair; `n <= 0` yields
        `Ord a, Num a` and the bare literal `5` never grounds `a`.  The subject of the test is
        RETURN-position inference (the `: Bool` ascription), not the argument type — the
        self-recursive sibling `mkPR` two lines up has the same shape and does NOT report,
        so the ambiguity is an artifact of the mutual pair, not of the feature under test.
        FIX: ground the argument (`pingP (5 : Int) : Bool`).  Return-position inference is
        untouched.

submod.mdk:28:15  Could not deduce 'Base m' from the signature of 'mkSub'                  (D)
        `mkSub : Sub m => a -> m a`, and `interface Sub f requires Base f`, so `Base m` is a
        SUPERCLASS of a declared constraint.  Superclass entailment works — the identical
        code in ONE file checks clean (exit 0, `mkSub : Sub b => a -> b a`), and so does
        `./medaka check test/ported/submod.mdk` on its own.  It fails only when the module is
        reached through the multi-module path.  Minimal 2-module repro filed; NOT worked
        around here, because adding `Base m =>` would mask a live false-reject that also
        breaks `medaka run`.

474:38  cannot derive 'Num' for 'Dist'                                                    (B)

        `Generic` — its own comment says the specialized newtype derivers "this port has not
        taken", so a newtype "genuinely cannot derive them here".  The interpreter reaches

        corpus exists to pin.  ISOLATED to test_eval_divergent_ported.mdk.

        one of these five right-hand sides is an `n => …` lambda (lines 842-856).  Root cause,

        no location to give).  NOT worked around; ISOLATED to
