# Typechecker cell lifetimes

One row per piece of mutable typechecker state: the two module-level cells (`interners` in `compiler/types/tc_state.mdk`, `preludePreambleMemoRef` in `compiler/types/typecheck.mdk`), the fields of its bundle records (`ModuleCtx`, `GraphCtx`, `GraphRun`, `CrossRun`, declared in `compiler/types/tc_types.mdk`), the fields of the process's interners (`Interners`, `Lineage`), the fields of the records that carry the drive's configuration (`TcConfig`, `DriveInputs`, `TraceSink`) and of the context records that replace the old cells (`GroupCtx`, `DynCtx`, `SiteCtx`), and the cells outside the file that a drive reads or writes. It is the inventory the state-by-lifetime split works from.

Counts: 2 module-level cells (`types.tc_state` 1, `types.typecheck` 1); field rows `ModuleCtx` 3, `ModuleCells` 92, `GraphRun` 29, `CrossRun` 14, `GraphCtx` 19, `Interners` 2, `Lineage` 5, `TcConfig` 6, `DriveInputs` 9, `TraceSink` 8, `GroupCtx` 2, `DynCtx` 11, `SiteCtx` 3; 205 rows in the first table (the 2 cells and 203 fields), 7 rows outside the file and 5 beside the drive. The first table is pinned to the cell census by `test/arch_boundaries_test.mdk`.

Stage-6 denominators: met at `d111d97fc` (the sprint head after the last code slice of arch-p2-6d, the Phase 2 exit). The two module-level cells are `interners` and `preludePreambleMemoRef`; `perRun` (arch-p2-6c) and `graphCtx` (arch-p2-6d) are deleted. The module record is a parameter of its readers or comes through `DynCtx.dcModule` and `SiteCtx.sxModule`; the graph record is a parameter of the drive layer or comes through `ModuleCtx.mcGraph`. The 6c frontier counts (`graphCtx` 276 / 1457 / 463 at the head of arch-p2-6c, over `compiler/types/typecheck.mdk` with the carrier holders as stops) describe the cell that is now gone.

Columns: `name | holds | lifetime | owner-today | writers | reset | target | interface-fills | source | issue`.

- `lifetime` is the measured one, from the writers and the reset site, not the declaring comment: `process` (never reset), `config` (set by the driver before the drive), `graph` (re-minted per graph), `module` (re-minted per module), `group` (reset per check group), `run` (saved and restored around one walk), `unknown`.
- `target` is where the cell lands: `TcEnv` (run), `GroupCtx`, `ModuleCtx`, `GraphCtx`, `TcConfig`, `DriveInputs` (immutable publication selection), `interner` (stays process-wide), `delete` (dead or test-only).
- `interface-fills` is `yes` when a loaded ModuleInterface would have to populate the cell for an importer to typecheck against the module without re-checking it. `source` then names the published fields it derives from (`cpSchemes cpCore cpEvidence cpDispositions`), `derived(<field>)` where a computation over one reproduces it, or `none`. `cpBinders` does not exist in `CheckedProgram` at this base, so binder rows have source `none`.
- `GraphCtx`'s sub-record and configuration fields (`GraphCtx.crossRun`, `GraphCtx.graphRun`, `GraphCtx.config`, `GraphCtx.trace`) are rows of their own; their fields are the rows that carry the lifetimes. The graph record itself has no cell: `mintGraphCtx` returns it, every reader takes it as a parameter or through `ModuleCtx.mcGraph`, and a reader after the drive reads `DriveOutputs` (a test that observes the record calls a driver's `...Graph` sibling, which returns it). `DriveInputs` is not a cell: it is the drive's first argument, and its field rows say who builds it. `DriveOutputs` (`tc_types.mdk`) is not a cell record either: it is the plain data a drive returns, frozen at the drive's end and holding no `Ref`, so it has no rows. Its field `doEffvarNext` (the drive's effect-variable counter at its end) seeds the `effvarCounter` of the own graph record that `lastInvocationOps` builds (`typecheck.mdk`, `lastInvocationOps`); it is a value, not a cell, and has no rows.
- "Interface fills (input to playbook C1)", after the second table, is outside the parsed tables: it names, for each row the awk `$8=="yes" && $9=="none"` selects (and for the caveat rows), the field that owns it, its producer and its kind.

## Interface fills (input to playbook C1)

The rows of the typechecker tables whose `interface-fills` is `yes` and whose `source` is `none` (the strict rows), plus the rows whose `source` is `derived(cpSchemes)` that the cell table's first review left as a caveat (the function-versus-method split of the predicate slots, and `dictEligible*`). A loaded `ModuleInterface` would have to restore each one for an importer to typecheck against a module without re-checking it. `kind` is what C1 needs: a `computed once` value is rebuilt from the loaded graph's declarations in one call; an `accumulated` value grows as each module is checked, so C1 restores it from each loaded module's interface. The two counters `GraphRun.tyvarCounter` and `GraphRun.effvarCounter` are also `derived(cpSchemes)` but are id sources, not interface content, and are not listed.

### Kind to field (the interface value, `types.prelude_interface`)

The interface value is `PreludeInterface` (`compiler/types/prelude_interface.mdk`). `freezeInterface` reads each row's cell into one of its `pi*` fields, and `thawInterface` writes the fields back into fresh cells. The correspondence by `kind`:

- *accumulated* rows map to the `pi*` field that holds the cell's value: `CrossRun.universeFunNamesRef` to `piFunNames`, `universeMethodDispatchIdxByIdRef` to `piMethodDispatchIdx`, `universeDataCtors` to `piDataCtors`, `universeCtorPop` to `piCtorPop`, `universeRecordPop` to `piRecordPop`, `crossModuleFunPredicateSlotsRef` and its `Qual` twin to `piFunPredicateSlots` and `piFunPredicateSlotsQual`, `crossModuleFunConstraintDeclaredRef` and its `Qual` twin to `piFunConstraintDeclared` and `piFunConstraintDeclaredQual`, `crossModuleMethodPredicateSlotsRef` and its `Qual` twin to `piMethodPredicateSlots` and `piMethodPredicateSlotsQual`, `GraphRun.ctorExistentialsRef` to `piCtorExistentials`, `GraphRun.anyExistentialsRef` to `piAnyExistentials`.
- The two named extras map to `pi*` fields too: `CrossRun.builtinClassesRef` (computed once, from the prelude's declarations alone) to `piBuiltinClasses`, and `GraphCtx.builtinExternNamesRef` to `piExternNames`, which is not the cell's value: the cell is the process's union over every catalog build, and the field is the catalog the prelude's own runtime declarations build alone (`checkCoreMemoized` builds it with `externSigsToMap`), which a thaw unions back into the cell.
- *computed once* rows are not fields. They are recomputed by `graphPreamble` on every drive, hit and miss alike: `GraphCtx.effectDomains`, `declEnvsRef`, `abstractRecordTypesRef`, `argDispatchIdxByIdRef`, `mangledShadowMapRef`, `markSetsRef`, `dictEligibleRef`, `dictEligibleSetRef`.
- Exception rows, with no `pi*` field of their own: the id counters (`piTyvarNext`, `piEffvarNext`, restored through `GraphRunSeed`), the standalone name set (`piStandaloneNames`), `cpCore` (`piCore`, thawed into `ModuleBindings` and the `CrossRun` schemes), `CrossRun.crossModuleSchemeOblsQualRef` (not a field: `thawInterface` starts it empty on every drive; the rows base left there are read only through explicit imports of core, and each name is also in `crossModuleFunConstraintDeclaredQualRef` and, by bare name, in `coreSchemeObligationsRef`; two-arm check and LSP probes on renamed, aliased and wildcard core imports were identical), and `selectedProfile` (not frozen: its value is the cache key's IO join, `preludeCacheHit gen join`).

Settled readers of the state the interface restores (one sentence each; the rows are the test named in parentheses):
- `cpEvidence` (`drivenEvidence`): a cold drive publishes the evidence a warm drive publishes, with no core rows in it (`publish_test.mdk`, "P -> Q -> P").
- `cpBinders`: on the diagnostics arm it is the same on a miss and on a hit.
- `GraphRun.scopeStore` (read by `scopeFrameStats`): core leaves no scope frame in the drive's run on either path, so the frame count is 4 on every run (`typecheck_test.mdk`, "every run leaves the same frame count").
- The first module of `checkModulesK`: its seed is an empty oracle with no warnings; core's record no longer carries the spurious empty-oracle warnings (`typecheck_test.mdk`, "checkModulesK seeds its first module").

The module interface owner basis adds detached declaration data to the existing cache, never a query closure, request or manifest. The capture set and invocation resolver are drive-local and are not retained; only requested owners are read on a serve hit.
