When it drifts, re-derive.

## What this directory is
Stage five of the pipeline (`ARCHITECTURE.md` section 1), layer `types` in A1: above `frontend/`,
below `ir/`. It consumes the resolved AST and produces the dict-passing-elaborated program plus
the side tables `ir/`, `eval/` and `backend/` read (dispositions, runtime types, route words).
`typecheck.mdk` is the graph driver and elaboration entry; the inference core lives in `tc_infer` and `tc_infer_records`, with the rest extracted from it into the other `tc_*` modules.

## Cell lifetimes
`CELL-LIFETIMES.md` lists every typechecker cell (the 2 module-level cells: `interners` in `types.tc_state` and `preludePreambleMemoRef` in `types.typecheck`, and the fields of the bundle records `ModuleCtx`, `ModuleCells`, `GroupCtx`, `GraphCtx`, `GraphRun`, `CrossRun`, `Interners`, `Lineage`, `TcConfig`, `DriveInputs`, `TraceSink`, `DynCtx` and `SiteCtx`) with its measured lifetime, target home and whether
an interface load would have to fill it; its opening paragraph carries the per-record and per-lifetime counts, so none is restated here. The prelude interface cache (`preludeCacheRef`, `types.prelude_interface`), `preludeElabCacheRef` (`types.prelude_elab`) and the evidence segment `preludeEvidenceRef` (`types.route_key`) are among its rows outside the bundle records; each is process-lifetime and reset never. `ModuleCtx.mcLoc` is a scoped value, not a cell: a construct hands its sub-walk an updated copy of the record, and the diagnostic location is the span of the innermost enclosing construct. Its "Interface fills" section names the producer and kind of each row playbook C1 restores.
The per-module cell counts are in `test/arch_goldens/cells.golden`.

## The prelude interface
The prelude's core pass is a value, `PreludeInterface` (`prelude_interface.mdk`), cached once per compiler generation. `interface_sexp.mdk` encodes it to `stdlib/core.mdki`; `medaka interface write|show|verify` writes, prints and checks the file, and `make medaka` and CI's `setup-medaka` rewrite it. The check family, `doc`, `lsp`, `mcp` and `test` read it through `loadPreludeInterface` (`driver/build_cmd.mdk`) when the file's header (format version, source hashes, compiler fingerprint) matches, and seed the cache instead of running the core pass. A stale or undecodable file falls back to the core pass; `check` and the servers say so on stderr (`check --json` prints the line on stderr too, not in the envelope; `run --json` is silent), and `MEDAKA_STRICT=1` makes that exit 1. `MEDAKA_NO_INTERFACE=1` turns the load off.

## The prelude's elaborated trees
The tree arm (`GOutTrees`; `run`, the emitter child, `medaka test`'s eval drives) needs core's dict-passed `Decl`s, which an interface does not hold. `prelude_elab.mdk` holds them as a value (`PreludeElab`), cached once per compiler generation, and `interface write` writes them to `stdlib/core.mdke` beside `core.mdki` (same key components, its own format tag and digest). `graphPreamble` hits when the drive carries a prelude key (`DriveInputs.diPreludeKey`), and both the interface for its join and the elaborated value are cached for that key: it then skips `elabModuleStamp` on core, continues from `continueFromInterface`, and publishes core's evidence and binder rows merged with the drive's. Otherwise it elaborates core as before. The diags arm never reads the file. Ids cross the file by rule: `EvId` ordinals and `$k$lb` names restore the writer's counters before any mint, `BinderId` ordinals relocate by one offset at load, and the evidence index keeps a process-wide prelude segment (`types/route_key.mdk`) so a drive's index holds slots for its own entries only. `loadPreludeElab` (`driver/build_cmd.mdk`) judges the file; the verb's own process prints `prelude trees stale: …` once (an emitter child never does), and `MEDAKA_NO_INTERFACE=1` disables both files.

- **A1** — types imports `frontend/` and `support/`; `ir/` and `eval/` must reach its facts through `disposition`, `runtime_types` and `route_key`, not `typecheck.mdk`.
