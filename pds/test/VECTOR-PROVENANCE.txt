# pds/test/VECTOR-PROVENANCE.txt — provenance for every vector file under pds/test/
#
# WHY THIS EXISTS  (docs/design/ATPROTO-PDS-DESIGN.md §5, G5)
#   G5: "No golden is ever captured from our own implementation in Phases 0-1.
#   Capturing a golden records what the engine did, not what is correct; on a
#   protocol where correctness is defined by other people's implementations, a
#   self-captured golden is not weak evidence but *anti*-evidence, since it
#   converts a bug into the defended expected output."
#   The design also states G5 has NO mechanical enforcement, and names this file
#   as the remedy: "require every vector file to carry a committed provenance URL
#   and digest, and add a gate that fails on any vector file lacking one … a
#   ledger that self-drains, in the style of test/EXTERN-DOMAIN-LEDGER.txt".
#   The gate is pds/test/vector_provenance.sh.
#
# WHAT THIS LEDGER PROVES, AND WHAT IT DOES NOT
#
#   PROVES — mechanically, offline, on every CI run:
#     - every vector file under pds/test/ has exactly one [vector] stanza here;
#     - that file's CURRENT bytes still hash to the local-sha256 in its stanza,
#       i.e. nobody edited a vector after its row was written;
#     - every reference-impl row names an [impl] stanza that pins one
#       repo + version + commit, and no two [impl] stanzas pin the same id to
#       different commits — ONE answer key for the sprint, not one per slice;
#     - every key required for the row's kind is present and well-formed.
#
#   DOES NOT PROVE:
#     - that source-url was ever fetched, or that the bytes at that URL hash to
#       source-sha256. THIS GATE HAS NO NETWORK. source-sha256 is an audit anchor
#       for a human reviewer, not a checked column.
#     - that the recorded values actually came from the cited source. A row with a
#       correct local-sha256 and a fabricated source-url PASSES. This ledger makes
#       a self-captured golden into a written, attributed, falsifiable claim that a
#       reviewer can check by hand; it does not detect one.
#     - anything about expected values that are not in a vector file — inline
#       literals in a pds/**/*_test.mdk, or a .mdk data module, are invisible here
#       BY CONSTRUCTION. Put expected values in a vector file under pds/test/.
#     - a vector file placed ANYWHERE ELSE in the project (e.g. under
#       pds/lib/vectors/) — the gate PASSES, silently (MEASURED). This is
#       DELIBERATELY NOT MECHANIZED: widening enumeration to all of pds/ would
#       demand a row for pds/README.md, pds/medaka.toml, and every pds/lib/*.mdk,
#       trading a documented hole for a false-positive generator
#       (RUN-PDS0-009 F6). This is why the corpus-location rule below is an
#       IMPERATIVE, not just a description of what gets checked.
#     - a SYMLINKED corpus file's bytes: a symlink is enumerated and REJECTED
#       outright (never resolved), so the ledger makes no claim whatsoever about
#       bytes that live outside this repository.
#     - a corpus file named *.sh: it is excluded from THIS gate's enumeration by
#       name, same as any *.mdk. That is a compensating control in a DIFFERENT
#       gate, not this gate's own coverage — committing e.g.
#       pds/test/vectors/foo.sh reds test/diff_compiler_ci_shard_coverage.sh
#       (it enumerates every tracked *.sh and no shard pattern selects that
#       path), not this one.
#     - that an [impl] stanza's commit: is actually a COMMIT. A well-formed
#       40-lowercase-hex value that is a TAG OBJECT rather than a commit passes
#       every well-formedness and pin-agreement check here. The pin is checked
#       to be single-valued; it is NOT proven to be a commit. Derive it with
#       `git rev-parse '<tag>^{commit}'` — never a bare `rev-parse` or an
#       `ls-remote` on an annotated tag ref, both of which can hand back the
#       tag object's sha (RUN-PDS0-016).
#
# VECTOR CORPORA MUST LIVE UNDER pds/test/. That is not merely descriptive —
# it is the instruction to every consumer slice (S-sha256, S-encodings,
# S-field, S-scalar, …): a file placed elsewhere is invisible to this gate
# (see DOES NOT PROVE, above). The gate's actual enumeration (mechanism, not
# policy): every regular file AND every symlink under pds/test/ at any depth,
# EXCEPT *.sh, *.mdk, and this file. A .md under pds/test/ therefore needs a
# row too: put prose in pds/README.md instead. A symlink is enumerated and
# then REJECTED with a named failure — never silently dropped, never followed.
#
# FORMAT
#   Stanzas. A stanza opens with [impl] or [vector] alone on a line and runs to
#   the next stanza header or EOF. Inside: "key: value", one per line; the value
#   is the rest of the line, surrounding whitespace stripped; values are
#   single-line (no continuations). Blank lines, and lines whose first non-blank
#   character is '#', are ignored anywhere. An UNKNOWN key is an ERROR, not a
#   comment — that is the typo guard. A stanza header other than [impl] or
#   [vector] is ALSO an error, naming the line — same typo guard, opposite
#   failure direction: a mistyped header (e.g. [vecter]) must not be silently
#   skipped, taking its vector file's row with it.
#
#   [impl] — one per reference implementation used anywhere in this sprint.
#     id         short handle; [vector] rows reference it            REQUIRED
#     repo       URL of the source repository                        REQUIRED
#     version    release tag or version string                       REQUIRED
#     commit     40 hex — the exact commit corpora were generated at REQUIRED
#     retrieved  YYYY-MM-DD                                          REQUIRED
#     notes      free text                                           optional
#
#   [vector] — exactly one per vector file.
#     file           repo-relative path of the vector file           REQUIRED
#     local-sha256   64 hex of THAT FILE's bytes; gate recomputes it REQUIRED
#     kind           published-artifact | reference-impl             REQUIRED
#     source-url     where a reviewer goes to check this             REQUIRED
#     extraction     how the values got from the source into the file REQUIRED
#     retrieved      YYYY-MM-DD                                      REQUIRED
#     consumer       slice-id + issue with its handle                REQUIRED
#     source         artifact title/identifier
#                                      REQUIRED iff kind=published-artifact
#     source-sha256  64 hex of the fetched artifact's bytes, or the literal
#                    token UNAVAILABLE
#                                      REQUIRED iff kind=published-artifact
#     source-note    why the artifact is not byte-digestible, OR why a withdrawn
#                    edition is still the right answer key
#                                      REQUIRED iff source-sha256=UNAVAILABLE
#                                      OR the row cites a withdrawn/superseded
#                                      edition (RUN-PDS0-008 D1: disclosure is
#                                      the price of the widened in-class set)
#     impl           an [impl] stanza's id
#                                      REQUIRED iff kind=reference-impl
#     notes          free text                                       optional
#
#   THE TWO DIGEST COLUMNS HAVE DIFFERENT JOBS. local-sha256 is GATE-CHECKED and
#   catches drift after the fact was recorded. source-sha256 is AUDIT-ONLY and is
#   what lets a human re-fetch the artifact and confirm the bytes. Neither can
#   detect a fabricated source-url; see DOES NOT PROVE, above.
