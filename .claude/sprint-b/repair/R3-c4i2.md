### P1 — `implDefinesMethodAt` prefix-vs-graph skew ⭐ THE ONE THAT DISCRIMINATES THE GAP

Discriminates: **organ 2.** The impl is in module `n`, the use site in module `m`; `m` does not
import `n`. In one import order `n` is inside `m`'s `accAll` prefix; in the other it is not.
`implDefinesMethodAt` therefore answers True/False *for the same program*, choosing `dictName =
"lt"` vs `"compare"`, and `argImplDictRoutesForEncl` then selects over the graph-global `IE` with a
**different method name** — different evidence for the same goal.

The shape needs three things at once, and each is load-bearing: (i) the method must be one of
`lt/gt/lte/gte/min/max` — `innerDefaultMethod` (`:15731-15736`) is a hardcoded name list, so any
other name makes the two arms identical and the probe **vacuous**; (ii) the impl must **define `lt`
and NOT define `compare`**, so that the two names select *different* rows (method-set membership is
`implMethodNameTc methods` = DEFINED methods only, `:18051`); (iii) the impl must carry `requires`,
or it is not in `ImplBuckets` at all (`implEntryOf`, `:18042-18045`).

```
-- /tmp/r3p1/iface.mdk
public export interface Cmp a where
  lt : a -> a -> Bool
  compare : a -> a -> Int
  compare x y = if lt x y then 0 - 1 else 1

-- /tmp/r3p1/base.mdk
public export data Box a = Box a
import iface.{Cmp}
export impl Cmp Int where
  lt x y = x < y

-- /tmp/r3p1/n.mdk        -- the impl `m` never imports
import iface.{Cmp}
import base.{Box(..)}
export impl Cmp (Box a) requires Cmp a where
  lt (Box x) (Box y) = lt x y

-- /tmp/r3p1/m.mdk        -- the USE site; imports iface + base, NOT n
import iface.{Cmp, lt}
import base.{Box(..)}
export useIt : Box Int -> Box Int -> Bool
useIt a b = lt a b

-- /tmp/r3p1/main.mdk     -- PERMUTE THESE TWO LINES
import m.{useIt}
import n
main = println (useIt (Box 1) (Box 2))
```

**Expected under DICT, both orders identically:** `True`. **C4** (`docs/spec/DICT-SEMANTICS.md:1312-1315`)
— *"Two modules resolving the same predicate must consult the same instance set and produce the same
evidence"*; **C3** (`:1297-1303`) — entailment is a function of the goal and scope, never of search
order; **§8 I5** — candidacy is graph-global, so `n`'s impl is a candidate at `m` under both orders.

**What a failure looks like** — and note it is *not* primarily an output difference:
- **The grader is the IR.** `./medaka build main.mdk -o /tmp/r3p1/out --keep-ir` under both orders,
  then `diff` the two `.ll` files. Under C3/C4 they must be **byte-identical modulo module ordering
  of definitions**. A differing `call @mdk_impl_Cmp__Box_a___lt(...)` **argument count** between the
  two orders is the failure: the missing-`requires`-dict arity skew, i.e. exactly SA-4c's class
  (`typecheck.mdk:19170-19186`), which produced `check` 0 / `build` 0 / **binary 139**.
- **S0 signature:** one order prints `True`, the other prints `True` **from a binary with a dict
  slot filled by a value cell** — or exits 139. Either way, exit 0 on the accepting order means the
  loud channel is not watching.
- ⚠️ **The `check` verb cannot see this.** `keyForSite` and the whole `resolve*` stamp family are
  **elaborate-only** (`:18358-18376`): `medaka check` on a multi-module project never stamps a
  route. **Grade with `run` and `build`, not `check`.**

### P3 — rigid goal with the dict in scope (#203 shape)

Discriminates: **§3 precedence.** Phase 0 asked for this explicitly: identity stamping *faithfully

required to equal what an independent `inst` would build at a rigid use-site goal — and where they
