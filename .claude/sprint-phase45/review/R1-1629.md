## Findings

### F1 — S1 (loud breakage, regression on bystander code). `headTyconNameTy`'s widening reaches `implHeadTagsForIface`, a program-global impl-head CENSUS whose cardinality decides `T-AMBIGUOUS-INSTANCE`. A present-but-never-dispatched-to arrow or effect impl now HARD-ERRORS programs that base accepts.

**Site:** `compiler/types/typecheck.mdk:20138-20150` (`routeUndeterminedTop`) reading
`implHeadTagsForIface` → `implHeadTagForIface` (`:20162-20170`) → `headTyconNameTy`.

```
routeUndeterminedTop prog implTable keyTable iface
  | iface == "" = RNone
  | otherwise = match implHeadTagsForIface prog iface
    [] => RNone
    [tag] => RKey tag (argImplRequiresRoutes …)
    _ => reportAmbiguousImpl iface        -- pushTypeError "T-AMBIGUOUS-INSTANCE"
```

The PR gives `headTyconNameTy` a `TyFun` arm AND makes `headTyNode` peel
`TyEffect`. Both widenings turn a `None` (silently DROPPED from the census) into
a `Some tag` (COUNTED). So an impl that was invisible to this census now bumps
the tag count from 1 to 2 and flips the `[tag]` arm to the `_` error arm.

**Measured, two arms, same source files, only the compiler differs.**
BASE = `medaka` built at `aaa4371`; BRANCH = same worktree with the PR's
`compiler/` diff applied and rebuilt.

`p/c.mdk` — an arrow impl declared beside an ordinary `Int` impl, never dispatched to:
```medaka
interface C a where
  mk : Int -> a
  sz : a -> Int
impl C Int where            -- mk n = n ; sz n = n
impl C (Int -> Int) where   -- mk _ = (x => x) ; sz _ = 0
use : Int
use = sz (mk 3)
main = println use
```
```
BASE   run -> 3                                                   exit 0
BRANCH run -> c.mdk:14:6: Ambiguous instance for `C`. Cannot determine
              which impl; add a type annotation                   exit 1
```

`p/d.mdk` — identical but with `impl C (<Stdout> Bool)` instead of the arrow (the
`TyEffect`-peel half): **same flip**, `BASE 3 / exit 0` → `BRANCH exit 1`.

**The PR's own bystander fixture asserts this cannot happen, and it is wrong.**
`test/build_diff_fixtures/fun_head_impl_bystander.mdk` declares
`impl Sz (Int -> Int)` and `impl Sz (<Stdout> Float)` labelled *"present, never
dispatched to"*, and its header claims the fixture tests *"is the code that has
NOTHING to do with the change still correct?"*. Add ONE return-position method to
that same interface — the minimal way to make a constraint undetermined — and the
fixture's premise falsifies:
```medaka

  mk : Int -> a            -- the only addition to the interface
impl Sz (Int -> Int) where   -- sz _ = 5 ; mk _ = (x => x)   still never dispatched to
```

```
BASE   run -> 48                                                  exit 0
BRANCH run -> by2.mdk:22:34: Ambiguous instance for `Sz`.         exit 1
```

**A second, independent reader of the same widening — the multi-param grounding
path** — `groundOneObligation` (`:23107-23118`) → `uniqueImplTysFor`
(`:23124-23127`) → `implTysIfMatch` (`:23132-23141`, also `headTyconNameTy`).
`uniqueImplTysFor` returns `None` when MORE THAN ONE impl matches the tag, so the
`TyEffect` peel can silently un-ground an obligation by making a previously
unique candidate ambiguous:
```medaka
interface Conv a b where
  conv : a -> b
impl Conv Int Bool            where conv n = n > 0
impl Conv (<Stdout> Int) Char where conv _ = 'x'
main = println (conv 3)
```
```
BASE   run -> True                                                exit 0
BRANCH run -> e.mdk:10:7: Ambiguous instance for `Display`.       exit 1
```
Note the cascade: the lost grounding surfaces as a diagnostic about the PRELUDE
interface `Display`, not about `Conv` — a misleading message for a program the
user did not change.

**Why no gate saw it.** No program in the corpus pairs an arrow/effect-headed
impl with an undetermined-constraint site, so all 11 green checks are consistent
with this. This is precisely the AGENTS.md hazard — *"a program-global table … ask
what happens to a program that never touches it"* — and the fixture written to
answer it does not reach either reader (`groundOneObligation` short-circuits on
`listLen typarams <= 1`, and `Sz a` is single-param; and no constraint in the
bystander is undetermined).

**Is the new behaviour arguably CORRECT?** Partly, and this is the honest reading:
there genuinely ARE two impls of `C`, so `T-AMBIGUOUS-INSTANCE` is defensible and
matches what two ADT-headed impls already do today (verified: the same program
with `impl C Bool` in place of the arrow errors on BASE too). So F1 may be
loud-and-right rather than loud-and-wrong. **What is NOT defensible is that it is
undisclosed, unfixtured, and contradicted by the PR's own bystander fixture and by
§8's "the change is inert wherever no impl head is an arrow or carries an effect
row".** The PR presents its blast radius as "the route word"; it is also the
ambiguity verdict and the multi-param grounding candidate set. A ruling is owed on
each of the three readers, plus a fixture, plus a line in `unchecked:`. Whichever
way it goes, the fix "turns a path that returned NOTHING into one that returns
SOMETHING" at three readers and only ONE of them (dispatch) was analysed.

## Verdict

**No — not as it stands. Hold for an author ruling on F1.**

The engineering here is unusually good and I want to be explicit about that: the
head-projection SET was audited correctly (`TyVar` and `TyRow` untouched, `TyVar`
stays headless), the deliberate `headTyconNameMono` asymmetry is the RIGHT call
and is defended from `uOblIsDecidableNow`'s own closed-set derivation rather than
asserted, the `entail` repoint's "identical at every other head" claim is
mechanically true and I verified it through `headKeyOfCon`/`tabKeyName`, the
`__fun__` single-tag ruling survives a currying attack empirically, the fixtures
are genuinely hand-derived with a real permutation pair and a real lone-impl path,
and the golden re-cut contains exactly the six edited declarations and the import
and nothing else. Attacks 2, 3, 4, 5, 6, 8 from my brief all came back clean.

Attack 1 is where it breaks. The brief's question — *does this fix turn a path
that returned NOTHING into one that returns SOMETHING?* — was answered for ONE
reader (dispatch bucketing) and the widened projection has THREE. Two of them,
`implHeadTagsForIface` (the ambiguity census) and `implTysIfMatch` (the
multi-param grounding candidate set), change the verdict on programs that never
dispatch to an arrow or an effect head — measured, both arms, on the PR's own
bystander shape plus one added method. The fixture written specifically to prove
inertness does not reach either reader.

**What would make me merge:** a ruling that the new `T-AMBIGUOUS-INSTANCE` is
intended (I think it probably is — it makes arrow/effect impls consistent with ADT
impls), a fixture pinning it, and a `unchecked:`/§8 correction so the next reader
is not told the change is inert. If the ruling goes the other way, F1 is a
regression and `implHeadTagsForIface` needs its own decision about whether the
census should count synthetic head tags at all. F2 should be fixed in the same PR
(it is two comment lines in the module that defines the type). F3–F5 are follow-ups.
