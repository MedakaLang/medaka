# FINDINGS

## F1 — S2. The drain note's printed state-3/state-4 discriminator MISCLASSIFIES the most likely state-4 outcome for the #1182 fixture

`test/diff_compiler_iface_order.sh:474-478` prints, on every DRAINED row:

    check=1 WITH a codes= entry  -> the ambiguity is now REJECTED (state 3).
    check=0 with codes= EMPTY    -> selection is now deterministic and the
                                    program still compiles (state 4).

The gate's own FOUR-STATE TABLE is stricter — `:123` says state 3 reads
`check=1;codes=<some R-* code>;...`, **"a nonzero verdict WITH a diagnostic code"** where the code
is an `R-*` (resolve rejection). **The printed note and `test/IFACE-ORDER-LEDGER.txt`'s header
both drop the `R-*` qualifier**, and the printed note is what a future reader actually sees.

That matters because the `1182-unimplemented-iface-obligation-iface-order` fixture has **only
`impl FA Blob`**. If S1 lands alone (state 4 — deterministic identity-keyed selection, no
rejection) and the occurrence deterministically binds to **FB**, every ordering rejects with a
**type-stage `T-NO-IMPL`** — no ambiguity rejection at all. Demonstrated by construction (I removed
`impl FA Blob` to force exactly that convergence):

    FAIL 1182-… DRAINED — #1182 no longer diverges under interface-declaration permutation
      Observed signature: check=1;codes=T-NO-IMPL;schemes=;run=1:;build=1/-:
      ⭐ READ THE CONVERGED SIGNATURE …
        check=1 WITH a codes= entry  -> the ambiguity is now REJECTED (state 3).

A reader following the printed rule concludes **state 3 (Q1 landed, ambiguity rejected)** when the
truth is state 4 with the collision unrejected. `T-NO-IMPL` is not incidental: it is *already* the
code this fixture emits in one ordering today, so it is the single most likely convergence.

**Why it's wrong, not pedantry:** collapsing state 3 into state 4 is exactly the failure the
instrument was built to prevent — one notch over from the state-2/3 collapse the header names.
**Fix:** make the printed note (and the ledger header) say what `:123` says — `check=1` with an
**`R-*`** code is state 3; `check=1` with a **`T-*`** code is state 4 rejecting for a *different*
reason and is NOT the ambiguity being rejected.

## F2 — S2. The corpus structurally CANNOT discriminate a fix keyed by interface NAME from one keyed by MODULE-QUALIFIED interface IDENTITY — which is the sprint's actual named risk

All five fixtures are **single-file with two distinctly-named interfaces**:

    1182: FA/FB   1620: Alpha/Beta   negative-1182: A1/A2
    controls: C1/C2, E1/E2

`.claude/HANDOFF.md:16-23` states the standing requirement as *"Phase 4 must key frozen
admissibility by **INTERFACE IDENTITY** — if it freezes admissibility computed by the current
selector, it freezes the order-dependence."* The discriminating program for
name-vs-module-qualified-identity is **two same-named interfaces in different modules**. That
program cannot be added to this corpus, in two independent ways:

1. Two same-named interfaces cannot coexist in one file — measured:
   `interface Foo` ×2 in one file → `<unknown location>: Duplicate interface: Foo`.
2. The gate permutes **only the entry module's** declarations, so a case whose second `Foo` lives
   in an imported module has n=1 in the entry and is a hard failure, not a case — measured, I added
   such a probe:
   `FAIL multimodule-probe   PERMUTER: need >=2 top-level interface declarations, found 1`

**Consequence when the fix lands:** a fix that keys by bare interface **name** and one that keys by
module-qualified **identity** produce the *identical* converged signature on every fixture here.
The gate reds `DRAINED` for both and the reader reads "state 3 or 4 — done", while the cross-module
`Foo`/`Foo` collision is still live.

The scope limit itself IS disclosed (gate `:85-87`, PR body "nearest miss"), but it is filed as a
*coverage footnote* — "a defect decided by an IMPORTED module's interface order is NOT covered". It
is never connected to the FOUR-STATE TABLE, which is the artifact's headline claim. That is the
classic **claim reaching past its evidence** shape: the disclosure exists but does not qualify the
claim it undermines. **Fix (cheap, doc-only):** in the FOUR-STATE TABLE, say that the corpus
discriminates *"scoped beyond the bare method name"* from *"not scoped at all"*, and that it
CANNOT discriminate interface-name scoping from module-qualified identity scoping, naming the
`Duplicate interface` reason it cannot.

## F3 — S3. The `schemes=` cell is inert across the entire corpus — it grades nothing

The header (`:57-64`) presents `schemes=` as one of five load-bearing channels, justified as
*"exit 0, same printed value, but a binding INFERRED AT A DIFFERENT TYPE — which is what 'a
different interface won' looks like when the values coincide."*

Measured: **every** signature this corpus can produce has `schemes=main : Unit\n` or `schemes=`,
and which one is a pure function of the `check=` exit code:

    check=0;codes=;schemes=main : Unit\n;run=0:11\n;build=0/0:11\n
    check=1;codes=T-NO-IMPL;schemes=;run=1:;build=1/-:
    check=0;codes=;schemes=main : Unit\n;run=0:False\n;build=0/0:False\n
    check=1;codes=T-TYPE-MISMATCH;schemes=;run=1:;build=1/-:

Every fixture's only top-level binding is `main`, always `: Unit` (bare `check` filters the dump to
the user's own bindings), so the channel is 100% redundant with `check=`. The "coincident value,
different inferred type" case the header sells — which is precisely the *state-4-but-wrong* risk
the drain note warns about — **is exercised by no case in the corpus.** Not a false green today;
it is a claim about the instrument's sensitivity that the corpus does not back. **Fix:** add one
case with a top-level non-`main` binding whose inferred scheme differs by which interface won, or
say plainly in the header that no current case exercises this cell.

## F5 — S3 (INHERITED, not introduced). A TAB in program stdout is unescaped while TAB is the record separator

`esc()` escapes `\`, `|`, `;`, newline — not TAB — while signatures are stored as
`printf '%s\t%s\n' "$ord" "$sig"` and read back with `cut -f2` (`:298`, `:385`, `:398`). A fixture
whose program prints a TAB would have its signature **truncated at the first TAB**, and truncation
can make two genuinely different signatures compare **equal** — i.e. a masked divergence, the
silent direction. No current fixture prints a TAB, so this is latent. **Identical code exists in
`test/diff_compiler_import_order.sh:254/352/365`, so this is a family-level pre-existing gap, not
something this PR introduced.** Noting it so it is not rediscovered; not a merge blocker.

## F6 — S3. Cosmetic: a comment line above an `interface` does not travel with it

The permuter's chunk rule starts a chunk at any column-0 non-whitespace line, so `-- FA does X`
directly above `interface FA` is its own chunk and stays put while the interface body moves. The
signature never compares text, so this cannot cause a wrong verdict — but a human debugging a red
who dumps a permuted file will see misattached comments. Worth one line in the permuter comment.

## Verdict

**Yes, I would merge it.** No S0 and no S1. The instrument is real: it reproduces the defect, it
provably moves the file, and all four of its red directions fire. The green is honest — the ledger
form is the right call and the author was right to flag the brief's "must land red" requirement
rather than silently comply.

**Do I trust it to tell the truth when the fix lands? Mostly — with one qualification I would want
recorded before Phase 4/5 read it.** It will correctly and loudly say *"the divergence collapsed"*
or *"the divergence moved"*. What it will **not** reliably tell the reader is *which* fix landed:
F1 makes the printed discriminator misread the most likely state-4 convergence for the #1182
fixture as state 3, and F2 means a `DRAINED` reading cannot distinguish interface-NAME keying from
the module-qualified IDENTITY keying the sprint actually requires. Both are **prose/scope defects,
not code defects** — F1 is a two-line edit to the drain note plus the ledger header, F2 is a
paragraph in the FOUR-STATE TABLE. Neither should block the merge; both should land before anyone
acts on a red from this gate.
