# Sprint families — rules that only apply to one kind of sprint

A rule that cannot be stated without naming the sprint's kind of work lives here, not in the
general sprint skills, so a sprint of another kind never pays for it. `sprint-plan` step 3 routes
a planner here when the sprint is one of these families. A retro adds a section or a line here
when its proposal fails the generality test (`.claude/agents/sprint-retro.md`, routing question
2). A family with its own series runbook keeps its rules in that runbook instead.

## Visibility or move migration

**The census is a name list**, not a per-row class narrative: it misses field reads, aliases and
names a sibling borrows through its subject's imports. Slices classify by un-exporting, running
the strict directory test, and reverting what breaks. When the first slice defers a row class for
a structural obstacle, the orchestrator strikes that class from the remaining packets and sends it
to Val, rather than letting each slice re-probe it. (R35 migration: 1 of 48 M3 rows landed over
four slices.)

## A §7 exit criterion that demands dead-code deletion

"Delete X, with a fixture that can fail" can be unfalsifiable as written: if the dead path is
already unreachable everywhere the tree can drive it, no fixture can go red before the fix, and
no fixture can prove the deletion safe. **Pre-license a second discharge form in the criterion
itself**: an N-way build differential (the code path forced live / forced dead / as-is, compared)
showing the path is unreachable by construction is an equally valid close, stated as such up
front. (`predicate-slots` paid 3 full rebuilds and 298 assertions to show the literal form was
unmeetable, then stopped mid-sprint for Val to accept the only evidence that existed.)
