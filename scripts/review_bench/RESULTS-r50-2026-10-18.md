## What the misses show

- **The per-class prompt names R19 without stating it.** The row says
  "a reason valid under R19 (R50)". The per-class prompt carries only its own
  row, so it never sees R19's four kinds. The battery prompt holds the whole
  rubric, including `suppress.invalid-reason`'s list. Three misses come from
  this gap:
  - the per-item judge passes the ruled instance, RB-0566;
  - the confirm step passes RB-0569 and RB-0572.

  Each of those judges said it "could not check against R19's text". The
  battery flags all three. The fix is to state the four kinds in the
  `dup.cross-file` row, from the rule. It was not made here.
- **Generated evidence does not check a claimed constraint.**
  - RB-0572's twin claims a module-graph cost.
  - The entry already imports the module that exports the canonical copy.
  - The curated fact shows this, and the per-item judge flags the copy.
  - Generated evidence has no import facts, so the confirm step accepts the claim.
- **A partial difference.** RB-0575 (`printer.ppTyPrec`) names a real difference in
  its helpers. The judge argued that the clauses which coincide could be
  parameterised. Whether a difference in part of a function excuses the rest
  is a question for the project owner, so the item is now judgment.
