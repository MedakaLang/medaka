# MCP M0 baseline report

This is a pilot of one trial per task and arm, not population evidence or a causal comparison. The prompts were fixed without outcome-based tuning. The [pilot rows](pilot-results.json) contain all twelve independent judgments, costs, tool counts and evidence digests; [legacy operation samples](operation-samples.json) retain all 80 queued runs. A separate [interactive measurement matrix](measurement-samples.json) retains 80 new operation runs with serial request timing and kernel resource accounting. [Pilot details](PILOT.md) and [operation methods](OPERATIONS.md) give controls, reproduction commands and limitations. Private transcripts and paths are excluded.

All twelve host launches succeeded; that is separate from six correct and six incorrect answers. Each had one attempt, no denials or retries. The admission boundary allowed 30 operations and recorded attempts and denials; both arms used a verified CLI-only artifact, and the MCP arm additionally had the broker. Two MCP-arm trials made no MCP calls. Tool counts, individual rubric failures and fallback observations are in the rows. The repair agents reported read-only workspaces without a recorded write attempt; a same-mode synthetic append succeeded. No workspace restriction is inferred from their statements.

Each operation matrix has seven cases and a missing-binary control, five observations per arm: 70 collector successes and 10 expected startup failures. Collector success is not semantic correctness. Definition and reference lookups produced wrong or empty results; cross-file definition, selected dispatch and procedural identity were unsupported by these queries. Diagnostic responses included tool-level errors. The legacy changed-source test used a fresh session; the new interactive test checks bad source, edits the file, then checks corrected source in the same worker. Every repetition removes the expected type diagnostic. This establishes that specific same-session edit behavior, without changing any pilot grade.

Version 2 of the [budgets](../../../scripts/mcp_bench/budgets.json) freezes measured interactive round trips, absolute matched trace deltas, cgroup peak memory charges and an input-token context-cost proxy, with methods, sample counts, raw evidence hashes and rounding rationale. Warm round trips span 19.31–160.17 ms over 140 responses; startup is separate. Signed trace deltas span −40.58 to +22.03 ms over 70 matched pairs. Their absolute ceiling includes host/cache/scheduling noise and provides a guardrail, not an isolated estimate of trace-writing cost or evidence of speedup. Five repetitions per case support ranges and maxima, not p95.

The cgroup measurements include the supervisor after membership, namespace init, worker and descendants; the collector stays outside. Session CPU spans 90.375–257.162 ms; peak memory charge spans 21,950,464–134,561,792 bytes. Memory charge is the named memory substitute, not RSS or retained heap. The twelve preserved host input-token observations span 10,491–70,893 tokens. Cumulative input tokens, including cached input and repeated turns, are a context-cost proxy; private context occupancy stays unknown. Pilot CPU/RSS, read counts and wall timestamps remain null; no timestamps or resources are reconstructed retroactively. New operation timing uses monotonic offsets; its UTC start/end were also not captured. Allocations and retained heap remain unmeasured. The offline handshake of at most two seconds remains an untested hypothesis for the next sprint.
