# Experimental stdio lease: blocked transport handoff

The Linux experiment separated fixed-site trusted Null stream setup from caller content opens. Null and Piped workers launched, produced external markers, exited and were reaped; Piped preserved `5749524500ff0a` and EOF. The 72 endpoint alias cases and nine caller `/dev/null` operations refused without consuming input or writing the endpoint. Nested and concurrent attempts, rollback, identity and authority-leak controls were observed. Directory fsync was refused; disabling the type guard made the control succeed. These results cover the experimental owner path, not an enforced lease.

A compiled public-stdlib target established a specific transport blocker. With legacy stdin excluded, staggered bytes `80` and `ff` remained unread. With exclusion disabled, `readExactly` consumed the first short nonblocking prefix while returning `None`, and replaced non-UTF-8 bytes with `efbfbd`. The complete-input control also produced replacement bytes. The experiment is **blocked**, `qualified=false`: it does not establish that private byte transport is impossible.

The next prerequisite is explicit authorization for a private scratch lease-transport ABI and a compiled target that can invoke it, while legacy stdin stays excluded. Then prove admission and history synchronization, endpoint identity and same-fd use, resolver and output exclusion, release and error-retained ownership, parent-fd assumptions, acknowledged producer/consumer overlap, backpressure, deadline/cancellation and committed-prefix behavior. The observer's structured qualification row enumerates all 14 unexecuted requirements. No production semantic change or public API follows from these observations.

The evidence assumes Linux anonymous nonblocking pipes. It does not exclude hostile external descriptor holders or privileged tracers; it does not prove protected-manager deployment, owned-tree containment or macOS qualification. The descriptor experiment remains a separate historical result: its common content type policy blocked real Null setup. Its inputs and pins remain unchanged.
