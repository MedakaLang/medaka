# Jev judgment tools: calibrated judgments between lint and LLM review

**Status:** PROPOSED, 2026-09-16. The census half is built (`scripts/jev/`);
the roadmap is filed as epic #3117 with milestones J-CENSUS, J-REVIEW, and
J-NATIVE. J-NATIVE is parked as of 2026-09-17 and section 5.1 says on what
condition it unparks. Tracking is on the issues; this document is the design
and the measured record.

## 1. The niche

Medaka has two ways to keep code in shape. `medaka lint` is mechanical,
exact, and gated: a rule fires only on a shape the AST walker can prove, and
the max ratchet keeps the tree clean of every gated rule. A full LLM review
pass (the `style-review` and `pr-review` skills) can judge anything but is
slow and expensive, so it runs once per sprint over a diff and cannot look at
the whole tree.

Between them sits a class of style question that needs judgment but not
reasoning: does this comment narrate history instead of stating a constraint?
Would these nested matches read better as a `do` block? Does this helper
reimplement a stdlib function under another name? The linter cannot express
these, and the crusade's own status record says the detector half is where it
is weak (#2276). Val's framing on 2026-09-16: fill the niche between the
purely mechanical rules and the expensive reasoning pass.

TypeSafe's Jev model is built for exactly that shape. It takes a JSON state and
a map of typed questions and returns only typed answers: a Choice picks one
option and returns a probability per option plus a confidence; a Noul returns
the probability that a yes/no holds; a Score returns a weighted position on
ordered levels. It never generates text, never explains, and answers each
question independently. Requests take about a quarter second and cost cents
per thousand. Live documentation: <https://docs.typesafe.ai/llms.txt>.

## 2. What was measured

One experiment, 2026-09-16, `jev-latest`, 160 items hand-labeled by one reader
after reading each in full. The labels are the expensive-LLM baseline Jev is
meant to approximate, so every number below is agreement with that reader, not
truth. The corpus is `scripts/jev/eval_corpus.json` and the numbers are
regenerated by `make jev-eval`; if this table and that output disagree, the
output wins.

### 2.1 Comment register (100 blocks, prose only)

| Question | AUC | Best operating point | Regex census, same sample |
|---|---|---|---|
| narrates history | 0.99 | precision 0.96, recall 0.91 at 0.75 | precision 0.81, recall 0.72 |
| belongs on an issue, not in source | 0.99 | precision 0.85, recall 1.00 at 0.75 | no class |
| register level 0 to 3 (Score) | rank corr 0.82 | mean error 0.46 levels | no class |
| reviewer-addressed prose | 0.91 | precision 0.72, recall 0.75 at 0.65 | precision 0.82, recall 0.38 |
| contradicts the code below | 0.91 | unusable: yes on 81 of 100 | no class |

The history question beats the regex census outright and removes its known
false positives: the three instrumental "used to" hits in the sample
(`used to reconstruct`, `used to track`, `used to refuse`) all scored under
0.2. Calibration holds at the extremes and over-predicts in the 0.6 to 0.8
bucket, which is why the operating threshold is 0.75, not 0.5.

The mismatch question failed as posed: given a comment and the code fragment
below it, the model treats any detail the fragment does not show as a
contradiction. It is retired (section 4.3) and #3121 owns the replacement.

### 2.2 do-syntax candidates (60 declarations, the language test)

The existing rule `rule-bind-chain-to-do` in `compiler/tools/lint.mdk` fires
zero times tree-wide; the max ratchet exhausted it. Only one of the 60
sampled declarations is a verbatim passthrough chain. The remaining underuse
of `do` is the uniform-handler shape: every level's failure arm does the same
thing (`Err e => dieMsg e`, `None => False`), so a `do` plus one wrapper is
equivalent. That is the shape the shipped question asks about.

| Question | AUC | Best operating point |
|---|---|---|
| uniform-handler chain | 0.96 | precision 1.00, recall 0.84 at 0.55 |
| readability gain (Score) | rank corr 0.84 | mean error 0.56 levels |
| convert / partial / leave (Choice) | accuracy 0.67; 0.88 at confidence 0.7 | |
| convert-or-partial vs leave | 0.99 | precision 0.88, recall 1.00 at 0.80 |

Nearly every three-way miss is convert versus partial, a line the labels drew
by rule of thumb, and Jev's confidence on those sites is low. The other cluster
is two-level chains with a shared default, labeled leave, which Jev calls
partial at confidence around 0.3. Both are policy questions, and low
confidence is the right signal for a policy question.

### 2.3 The novel-language control

The same 60 declarations were asked with the Medaka language notes and the
in-tree exemplar removed from the state. Ranking held: the actionable split's
AUC stayed at 0.98. The scale broke: every readability score inflated by about
one level, verbatim-chain false positives went from 6 to 36, and
recommendation accuracy fell from 0.65 to 0.57. Jev reads Medaka's shape
unaided; it needs the language facts in the state to calibrate what counts as
"convert". That is the documented TypeSafe guidance (do not rely on knowledge
in the weights when the fact can be supplied), and it makes the novel-language
risk a design constraint rather than a blocker.

## 3. Principles

1. **Code finds, Jev judges, the agent rewrites.** Enumeration is loose and
   mechanical (recall over precision); the model answers narrow questions
   about each candidate; code ranks and thresholds; a person or an agent
   applies the fix. Jev never generates the fix.
2. **Never a gate.** Every Jev tool calls an external API and answers in
   probabilities. It is a census or a review-seam input. It always exits 0
   and is never enrolled in `test/gates.toml`.
3. **Language facts go in the state.** Every question over Medaka source
   carries the relevant spec excerpt and an in-tree exemplar (section 2.3).
4. **A question ships only with a number.** Every shipped question has a row
   in the eval corpus and its precision, recall, and calibration recorded
   here. Change the question, run `make jev-eval`, read the numbers, then
   trust the ranking. The corpus stores each item's text inline, so it does
   not drift with the tree.
5. **Batch, cache, bound.** All questions about one candidate go in one
   request (TypeSafe measured 12x cheaper than one question per request).
   Answers are cached by content hash under `.jev-cache/`. Concurrency is
   bounded and the SDK's retry policy handles rate limits.
6. **Thresholds are read off calibration, not assumed.** The operating points
   above came from the calibration tables, and each differs from 0.5.

## 4. The style census: the question set

Owner: milestone J-CENSUS. Tool: `scripts/jev/jev_census.py`; usage in
`scripts/jev/README.md`.

### 4.1 Shipped

Comment blocks (every `--` block of two or more lines; state is the policy
sentence, the file, the block, and the code directly below it):

- `history` (Noul): narrates history or provenance rather than stating a
  constraint. Operating threshold 0.75.
- `offsite` (Noul): given the policy, belongs on an issue or design doc.
  Operating threshold 0.75.
- `reviewer` (Noul): written for a reviewer or narrating the change in
  progress; the criteria name the repo's own phrasings (`this slice`,
  `earlier cut`, `measured on this diff`, `see the report's Notes`). Weakest
  question; #3123 splits it.
- `register` (Score, four levels): the ranking key. Sorted descending with
  `offsite` and `history` as tie-breaks, the top of the list is the relocation
  roadmap for #2280 (#3119).

Declarations (every top-level declaration with two or more nested matches on
Result or Option constructor arms and no `do`; state is the file, the
declaration source, and the language notes with the `typecheckGate`
exemplar):

- `uniform_chain` (Noul): two or more successive levels over one monad whose
  failure arms share one shape and thread the success value.
- `readability_gain` (Score, four levels).
- `recommend` (Choice: convert, partial, leave). The ranking key is
  P(convert) + P(partial), threshold 0.80 (#3120).

### 4.2 Next

- Split `reviewer` into narrates-own-draft and argues-against-objection
  (#3123).
- Comment-versus-code mismatch as claim pairing (#3121): code pairs each
  backticked identifier and each checkable claim with the declaration, Jev
  judges the pair.
- Doc-comment register for `stdlib/*.mdk` against the rules in
  `stdlib/README.md`: first sentence stands alone, no history or
  implementation notes inside the block. Same state shape as the comment
  half; not yet filed because the stdlib editorial pass (#2498 lineage) left
  the corpus clean enough that a sample is needed first to justify it.
- Suppression rationale quality: `rule-directive-reason` checks that a
  `lint-disable` carries a reason; whether the reason is a reason is a
  judgment.

### 4.3 Retired

- `mismatch` as "does the comment describe something the code below lacks":
  yes on 81 of 100. The fragment is the wrong evidence; see #3121.
- `verbatim_chain`: the lint rule owns it and the tree is clean of it.
- `meaning_change` ("would a naive `do` rewrite change behavior"): 59 of 60
  positives, so it carries no information once `uniform_chain` is asked.

## 5. Roadmap of tools

Ranked by how directly each maps onto a cookbook shape and onto a cost Medaka
pays today. Each is a filed child of #3117; the issue carries the acceptance
and the measurement plan.

| Tool | Milestone | Shape | What it replaces or adds |
|---|---|---|---|
| Comment register roadmap (#3119) and do-syntax batches (#3120) | J-CENSUS | census over the tree, ranked by Score | the hand-typed worklists the crusade forbids |
| Diff-scoped census in the style-review seam (#3122) | J-CENSUS | `--changed` over a sprint diff | judgment the cheap-model reviewer cannot afford |
| Claim-vs-evidence on sprint reports and PR bodies (#3125) | J-REVIEW | citation check: one Choice per claim against the diff and CI output | the reviewer catching a false headline claim, twice in a row on PDS |

| Trap-tag lookup (#3128) | J-REVIEW | line-by-line search over AGENTS.md's bracketed tags | agents not reading the whole file |
| Issue hygiene (#3129) | J-REVIEW | severity Choice, repro-presence Noul, title-body contradiction Noul, duplicate pairing | hand triage; #983's shape |
| Diagnostic rubric conformance (#3130) | J-REVIEW | Score per message against `compiler/ERROR-QUALITY.md` | the pending diag-census (#2302) |
| Renamed reimplementations and non-verbatim duplicates (#3131) | J-REVIEW | candidate pairing by signature, Choice with a none option | what `rule-stdlib-reimpl` and `rule-duplicate-body` structurally miss (#2248, #2651, #2885) |

The native Medaka client (#3132, milestone J-NATIVE) was a row in this table
until 2026-09-17 and is now parked; section 5.1 replaces it.

Explored and declined for now:

- **Idiom quotas** ("use `|>` here"). The `style-review` DECLINED register
  forbids density targets, and a Jev Score would only make a forbidden demand
  cheaper. A candidate-and-vet shape (linter proposes a rewrite, Jev compares
  the two readings) is legitimate but has no consumer until `lint --fix` is
  safe on comment-bearing declarations.
- **Golden regression versus improvement** ("did this golden change because
  the code got better?"). The highest-value review question, but it needs
  reasoning over semantics, not a calibrated judgment over text. Route to the
  reviewer; do not pretend a Noul answers it.
- **Anything as a required check.** Principle 2.

### 5.1 Parked: the native Medaka client (#3132)

Parked 2026-09-17 by Val's ruling. Not declined: it unparks only if TLS is
prioritized on its own merits. Nothing here is a reason to build TLS.

**The transport was never the cost.** The endpoint is one POST to
`/v1/systemone` with a bearer key, JSON in and out, no streaming, no
pagination, no signing; the failure statuses are 401, 422, 429, and 529. The
client half of `scripts/jev/jev_census.py` is about 100 of its 514 lines, and
`stdlib/json.mdk` is already the right shape, floats and integers kept apart.

**The cost is TLS, and Medaka has none.** There is no TLS library in
`runtime/medaka_rt.c` and nothing above raw TCP in `stdlib/runtime.mdk`. No
program in the tree performs an outbound HTTP request end to end; the only
connect-send-receive path is the fixture `test/net_fixtures/net_loopback.mdk`.
The HTTP half is also thinner than it looks from the outside: `stdlib/http.mdk`
parses requests and builds responses, which is the server direction, so the
client codec is `pds/lib/httpclient.mdk`, and moving that out of the PDS
manifest needs the stdlib proposal path.

Four ways past TLS, recorded so the survey is not redone:

1. A loopback TLS terminator, the pattern `pds/Caddyfile.egress` already
   establishes: dial `127.0.0.1` and let a reverse proxy hold the certificate.
   No new code, and the Python dependency becomes a Caddy dependency.
2. `runCommand` over `curl`, about twenty lines, working today.
3. A C shim over libcurl reached through `[foreign-libraries]`. `String ->
   String` is in the FFI v1 crossable set, but function pointers and structs
   are not, so libcurl cannot be bound directly, `mdk_` names are reserved, and
   `test/diff_compiler_llvm_ffi.sh` is the only gate that links C.
4. TLS 1.3 in Medaka. The primitives are not the hard part; X.509 chain
   validation is, and no gate here can prove it correct.

**Why Python is the cheaper side of the trade.** Section 7 already quarantines
the dependency: the tool is not a gate candidate, always exits 0, and is never
enrolled in `test/gates.toml`. The hundred lines a native client would own are
the ones TypeSafe changes underneath us, and principle 5's retry behavior is
the SDK's.

**The half that needs no client.** The interesting part of J-NATIVE was never
the transport but enumerating candidates from the real AST instead of line
regexes: the current enumerator finds a declaration by matching an identifier
at column zero and counts `match` occurrences, which bounds the census's
recall. A `medaka lint`-style enumerator emitting candidates as JSON for the
Python half to consume needs no TLS, no client, and no stdlib proposal. It
belongs on its own issue if enumerator recall ever becomes the limiting factor.

## 6. Evaluation discipline

The procedure, and the tips for moving a question's signal, are the
`jev-judgments` skill (`.claude/skills/jev-judgments/SKILL.md`). This section
records the rules it enforces.

- The corpus is `scripts/jev/eval_corpus.json`: 100 comment blocks and 60
  declarations with their text inline, one reader's labels, and the regex
  census classes for the baseline comparison. #3124 adds a second reader.
- `make jev-eval` prints, per Noul: precision and recall at 0.5 and at the
  best threshold, AUC, and a five-bucket calibration table; per Score: mean
  absolute error and rank correlation; per Choice: accuracy at confidence
  tiers and the confusion matrix. The control is `--no-language-notes`.
- A question change is accepted when the eval does not regress the operating
  point recorded here, and this document's tables are updated from the output.
- When a census recommendation turns out wrong during a drain, the site goes
  into the corpus with a `note`, so the question is re-measured against the
  case that fooled it.

## 7. Operational notes

- Key: `TYPESAFE_API_KEY` or `~/.config/typesafe/api_key` (mode 600), created
  from a terminal, never through an agent transcript.
- SDK: `pip install typesafe-sdk`, or `TYPESAFE_SDK_PATH` pointing at a
  `pip install --target` directory on a box without a venv.
- Cost at the cut: about 1,700 input tokens and 0.27 seconds per candidate.
  A whole-tree first run is a few thousand requests, run eight at a time.
- Source leaves the box. The repo is public; keep the census off anything
  that is not.
- A `.py` under `scripts/` is not a gate candidate; a `.sh` anywhere is
  (`[WEB-SH-IS-A-GATE]`). The tool stays in Python; section 5.1 says why, and
  on what condition that would change.
